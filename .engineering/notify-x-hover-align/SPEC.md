# 契约 · 通知卡 × 交互动画居中、正文加宽、右侧留缝

## 原话（照录）

> 通知卡的每一个x的交互动画好像位置没对好 x没在正中间 还有显示的宽度可以宽一点 现在左右两边留的空还是比较充裕的 还有x的交互动画最右侧和整条的交互动画最右侧几乎贴在一起了 需要调整一下

## 用户澄清（问答回合，权威）

- 「显示的宽度可以宽一点 / 左右留空充裕」→ 指的是**显示通知的正文内容区域**要更宽，不是 × 圆圈本身。
- 加宽的留白来源：**A（正文左侧缩进/圆点）和 C（卡片左右内边距）各压缩一点**。
- × 圆圈**保持 18px，只调整位置**。
- × 圆圈最右侧 与 整行 hover 底色最右侧之间留 **约 4px** 间距。

## 目标

在同一轮里修正通知卡 × hover 动画的三处视觉问题：让 × 字形在底圈里真正居中、把正文内容显示区加宽、让 × 底圈右缘与整行 hover 底色右缘留出约 4px 缝。

## 验收标准（AC）

| # | 判据（可判定） | 判定方式 |
|---|---|---|
| AC1 | 满 hover 时 × 橙色墨迹中心与圆形底圈中心的水平/垂直偏差：1× 帧 ≤0.5px、2× 帧 ≤1px（基线实测 1× dx=−0.5、dy=−0.5 DIP 偏左上） | `--probe notify-motion=hover` 出 1×/2× `f010`，Python 量墨迹 bbox 与圆底 bbox 中心并相减；贴数值 |
| AC2 | 240×300 正文节点（id+2）宽度由基线 159.5px 增大到 ≥165px（≥+5px）；实现方式是同时减小卡片左右内边距与条目左缩进（A、C 各压缩），× 仍为 18px | Rust 单测断言 `Tokens::notify(240,300)` 的 `pad_l/pad_r`/`item_indent` 变小、`close_w==18`、正文节点 rect.w ≥165；`--debug-layout` 打印佐证 |
| AC3 | 满 hover 时圆形底圈右缘 与 整行 hover 底色右缘 间距 = 4px ±0.5（1× 实测），且 × 命中节点完整包住圆圈 | 1× 帧逐像素：行底右缘 x 与圆底右缘 x 相减；单测断言 × 节点右缘 == 圆底右缘 且 == 行右缘−4 |
| AC4 | 无回归：× 仍只在行 hover 时出现、点 × 仍返回 `Hit::Remove`、退场/滚动/清除/状态动效与几何不变；除 A/C/×右缝外其它 token 不动 | 既有 hover/命中/动效单测全绿；`cargo test`(minicard-cards)、`cargo check`(minicard-bin) 绿 |
| AC5 | 1×/2× 前后对比图证明三处改动可见且无发糊/裁切；独立检验无 P1+ | 出图 + `engineering-verify` 子代理只读报告 |

## 非目标

- 不改 × 圆圈直径（保持 18px）、字号（13px）、放大比例（1.25×）、hover 时长（120ms）与缓动曲线
- 不改退场/滚动/清除/状态/组头入场等既有动效
- 不改其它卡片、web 主界面、config/数据层、Dock
- 不引入外部依赖；不新增第二套动效系统

## 未知与假设（标风险）

| # | 假设 | 风险 / 错了会怎样 |
|---|---|---|
| A1 | 居中=字形墨迹中心对齐底圈圆心（非 advance 盒对齐） | 若用户指的是 × 相对整行的位置，则 AC1 判据需改；已同时处理右侧 4px 缝，覆盖该读法 |
| A2 | 「A、C 各压缩一点」= pad 13→10、indent 24→18（正文 +8px） | 幅度若不符预期，用户可回契约调数值；已控制在温和范围 |
| A3 | 右缘 4px 缝 = 给行节点加 4px 右 padding（× 列整体左移 4px） | 若行 hover 底色右缘口径不同，缝隙测量会偏；用像素测确认 |
| A4 | 墨迹中心可用 DWrite overhang 的 (right−left)/2 与 (bottom−top)/2 精确求得 | top/bottom overhang 若语义与预期不符，垂直居中会偏；用 probe 像素复验，必要时回退到实测微调 |
