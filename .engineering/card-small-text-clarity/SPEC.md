# 契约：卡片小字清晰度诊断与优化方案

任务 slug：`card-small-text-clarity` · 档位：标准（诊断 + 定方案，不改产品代码） · 建立：2026-11-19

## 用户原话（照录）

> 量这个字 虽然我不知道具体分辨率和字体大小 但是你可以明显看出来我们的卡片要糊一点 怎么样才能提高我们卡片这种小字的清晰度

配图两张：① 浏览器标签栏「量子空间」中「量」字（对比参照，Chromium/WebView 渲染）；② 天气卡底行「空气质量 优」中「量」字（对象，native/D2D 自绘卡片）。

## 目标

1. 判定「卡片上的『量』等小字比浏览器标签糊」的根因，区分两条渲染栈，每条根因给代码/实测证据。
2. 给出按性价比排序、可判定（能证明真/假）的优化方案，明确先做哪条、哪条要用户拍板。
3. 纠偏用户假设「可能是分辨率/字体大小问题」——用已有实测证据说明它是不是主因。

## 验收标准（AC，均可判定）

- **AC1 栈归属**：证明浏览器标签字（清晰）与卡片字（糊）分属两条渲染栈，历史 `MC_SS`/补墨/gamma 只作用于卡片栈；给代码证据。
- **AC2 根因可证**：给出卡片小字糊的根因，每条有代码或实测出处；至少覆盖：灰阶 AA（不可子像素）、2× 降采样掉墨（字号越小掉越多）、字体 hinting、基线落位。
- **AC3 分辨率假设裁决**：用已量过的现场口径（DPR=1/zoom=1/1920×1080@100%）判定「分辨率/字体大小是否主因」，给事实出处。
- **AC4 今日变更影响**：判定 2026-11-19「全栈换系统雅黑」对卡片小字补墨的影响——补齐还是失效，给 A/B 证据（byte-identical）。
- **AC5 方案可判定**：每条方案含做法/收益/成本/风险/可复跑判据，按性价比排序，明确先做哪条、哪条要用户拍板。
- **AC6 落盘可续作**：方案写入 `docs/`，三件套齐全，新会话可独立读懂。
- **AC7 独立复核**：只读子代理按 `engineering-verify` 复核诊断与方案，输出结构化缺陷清单；实现者不自发合格证。

## 非目标

- 不改任何产品代码（native/*、web/*）、字体、构建配置。本轮只交付诊断 + 方案文档。
- 不重新设计卡片视觉、不迁移渲染栈。
- 不把「换字体」当主路（当日刚换雅黑，且历史已论证换字体不改 AA 模式）。

## 约束

- 平台：Windows；卡片 = native/D2D/DWrite 自绘（`native/minicard-*`）；透明预乘交换链。
- 现役：源码已切 `TextEngine::from_system("Microsoft YaHei")`（2011-19，工作树未提交，但为当前基线）；`MC_SS=2` 默认；gamma 2.2；`GRAYSCALE` 钉死。
- 工作树状态：`main.rs`/`live.rs`/`text.rs` 等有未提交改动（font-swap-ms-default），诊断以当前工作树为准。

## 决策记录

- 本轮为诊断 + 方案，边界与 `mainui-text-clarity` 首轮一致；区别：对象是 native 卡片栈而非 WebView 主界面栈。
- 两个栈不可混为一谈：`MC_SS`/小字补墨/gamma 是 D2D/DWrite 侧旋钮，对浏览器标签字无效；浏览器标签的清晰度来自 Chromium 子像素 AA + 系统字体 hinting。

## 第 2 阶段执行契约：方案 A spike（用户 2026-11-19 批准「先做 A 的 spike 试一下先」）

- **性质**：spike（只取证，不改产品代码）。产物 = 脚本 + dump + 对照图 + 判定写回本文/EVIDENCE。
- **核心设计（单变量，修正 O2 方法学缺陷）**：固定同一份 2× 栅格化内容（现有 `wx_ss2.bgra` = 480×360，雅黑 release `846E4908…F92C`），**只变降采样滤波器**：box（现役 DComp 盒式）/ bilinear / bicubic（≈D2D HIGH_QUALITY_CUBIC）/ lanczos，统一降到 1×（240×180）。这样隔离掉「ss1/ss2 对照里栅格分辨率变化」这个混淆变量——spike 本身就是 O2 指出的正确隔离实验。
- **参照**：ss1 原生 1×（`wx_ss1.bgra`）= 锐参照；ss2-box = 现役基线。
- **度量口径（三管齐下，避免单一阈值假象）**：
  1. 底行「量」字带（y157-168, x12-120）分层水平梯度计数（≥40/80/120/160、p90、TV），沿用 `measure_local_contrast.py` 口径，高阈值计数 = 高频细节保留指标；
  2. 逐带扣背景墨量（沿用 `measure_air_ink2.py`）；
  3. `stats()` 的 w50/mass（**只记录、不作判据**——权威口径相反，见方案 §4）。
- **判据（预先锁定，防事后挑数）**：CUBIC 类（bicubic/lanczos）相对 box，在「量」带**高阈值梯度计数（≥80/≥120）上更接近 ss1 锐参照**（即把 box 摊平的锐边补回一部分）→ 判定「值得落地 gfx.rs」；若与 box 持平或更差 → 判定「不值得，保留盒式」。需同时看墨量不得显著下降（掉墨 >5% 算代价）。
- **AC-S1**：同一 2× dump 上 4 种滤波器降到 1×，尺寸/口径一致，可复跑。
- **AC-S2**：三管度量对全部变体出数，box vs CUBIC 类 vs 两参照逐项对照。
- **AC-S3**：出放大对照图（底行「量」字带 ≥3×），主观目视辅助判据。
- **AC-S4**：判定明确（落地/不落地），写回 EVIDENCE/SPEC；产品代码全程未改。
- **非目标**：不改 `gfx.rs`（那是 spike 通过后的实施轮）；不做 9 卡回归/CPU/帧时（实施轮再测）；不承诺 CUBIC 一定赢（赢了才落地）。
- **环境风险**：PIL 的 bicubic/lanczos 是 CPU 高质量重采样近似，D2D `HIGH_QUALITY_CUBIC` 实现细节可能略有差异；spike 结论是方向性的，落地时须以真机 D2D 产物复核。

## 关键事实（勘察阶段直接取得，待 AC 引用）

1. 天气卡「空气质量」字号 `air_fs = 1.0625*r`，`r=16*k`（240×180 卡 k=0.75→r=12→air_fs=12.75px；320×240 k=1→17px）——落在 `SMALL_EMBOLD_MAX_PX=15` 覆盖区（`weather.rs:183`、`:146-186`）。
2. 该行 `text_node(..., 400)` 正文字重 400（`weather.rs:378`）。
3. 卡片栈：透明预乘交换链 → `D2D1_TEXT_ANTIALIAS_MODE_GRAYSCALE` 钉死（`gfx.rs:186-190`）；`MC_SS=2` 默认（`live.rs:43-52`）；DComp 0.5 盒式降采样（`gfx.rs:213-220`）。
4. 2× 盒式降采样掉墨，字号越小越多：11–12px −6.5~−10.1%，15–17px −8.3~−12.3%，49px 仅 −1.4%（`text.rs:39-48`、eval §6.6）。
5. gamma 2.2 是 DWrite 上限（更高逐字节相同）；`grayscaleEnhancedContrast>0.5`、`NATURAL_SYMMETRIC_DOWNSAMPLED` 在 2× 均无差异（`text.rs:49-52,1085,1098-1099`、eval §6.6）。
6. 小字补墨 400→500 真 Medium 面曾抵消掉墨 +9~12%（`text.rs:54-56`、eval §6.6 表）。
7. 2026-11-19 全栈换系统雅黑：雅黑无 500 真面，`css_weight(500)==css_weight(400)==400`，补墨升档被显式跳过、A/B dump 逐字节相同（`text.rs:76-89,407-416`；`font-swap-ms-default/EVIDENCE.md` AC/D4）。
8. 浏览器标签字：Chromium/WebView2 渲染栈，不透明背景可走子像素 AA + 系统字体 hinting（`font-and-aa-eval.md` §1 与 `mainui-text-clarity-plan.md` §2 主因 A 的权威来源）。
9. 现场口径 DPR=1 / zoom=1 / 1920×1080@100%（`font-and-aa-eval.md` §机器口径；`mainui-fix-plan-20261026.md` §3）。
