# 方案 A spike 结果 — 高质量降采样能否提升小字清晰度

时间：2026-11-19 · 用户批准「先做 A 的 spike 试一下先」 · 产物：`spike_route_b.py` + `spike_route_b_compare.png` · 产品代码未改。

## 判定（结论先行）

**不值得落地 gfx.rs（方案 A 的高质量插值核分支被证伪）。** 现役 box 盒式降采样在「量」字带上与 1× 原生锐参照的差距 ≤ bicubic/lanczos/bilinear——按执行前锁定判据（≥80/≥120 更接近 ss1 才落地），没有一种高质量插值核达标（bicubic 补回 −11/−30，lanczos +3/−4），「高质量插值核能补回小字锐度」不成立。

**关键前提（V4）**：此结论以「DComp 现役实际用盒式滤波」为前提，该前提来自 `gfx.rs:213-220` 的 0.5 MatrixTransform + 注释，**未经真机直接观测**。独立复核反事实验证：若 DComp 实为 bilinear，则 bicubic/lanczos 按同一判据会大幅达标、应判落地。故真机实施前应先确认 DComp 实际滤波核；本 spike 是在「盒式」前提下的方向性结论。

**第二分支（覆盖率补偿 k）不是「被证伪」而是「有效但要付过墨代价」**：k1.15 的高阈值补回 +16/+7 是全表最优，但这是加墨带来的（墨量 +10.6%，独立复核证明均匀放大 alpha 也能拿到同等 gain，非真实锐度恢复），且墨量 +10~20% 属明显过墨。锁定判据只罚掉墨、不罚加墨，故 k 分支的「过墨否决」是**补充判据**，已如实标注（V1）。若要「更肥的字」，它是独立于 gfx.rs 目标链改造的低成本选项。

## 设计（单变量，修正 O2）

固定同一份 2× 栅格化内容（`wx_ss2.bgra` 480×360，雅黑 release `846E4908…F92C`），只变降采样滤波器统一降到 1×：box（现役 DComp 盒式）/ bilinear / bicubic（≈D2D HIGH_QUALITY_CUBIC）/ lanczos，外加方案 A 第二分支 box+覆盖率补偿 k=1.15/1.30。参照：ss1 原生 1×（锐参照）、box（现役基线）。复用 `docs/verify/minicard_center/_ss_filters.py` 的 down/boost 与 `_aa_edge.py` 的 stats 口径。

## 判据（执行前锁定于 SPEC）

CUBIC 类相对 box，底行「量」字带高阈值梯度计数（≥80/≥120）更接近 ss1 → 值得落地；持平或更差 → 不落地，保留盒式。墨量掉 >5% 算代价。w50 不作判据（权威口径相反）。

## 读法

1. **CUBIC 分支证伪**：bicubic 的高阈值计数（≥80=218、≥120=116）比 box（229/146）离 ss1（247/157）更远，补回为负；lanczos ≥80 补回 +3（box 229→232，ss1 247，仍差 15，诚实说是「略优但仍未达标」）、≥120 更差。TV 也低于或≈box。→ 高质量插值核**没有实质补回**被摊平的高频细节。
2. **目视印证**（`spike_route_b_compare.png`，底行 3×，标签已改 ASCII）：box 与 ss1 几乎无差、笔画干净；bilinear/bicubic/lanczos 出现重影/糊边/振铃，明显更差；box+k 只是字更粗（加墨），边缘并未更锐。
3. **w50 陷阱**：bicubic w50=1.414、lanczos 1.617 比 box 1.308「更宽」，按 `_aa_edge.py:11`「更宽=更糊」它们更差；按 eval「宽软边藏台阶、Chrome 1.495」又像更接近 Chrome——**两套权威相反，再次证明 w50 不能单独当判据**（与主线一致）。
4. **覆盖率补偿 k 是「加墨」不是「变锐」**：k1.15 补回 +16 是全表最优，但独立复核证明均匀放大 alpha 也能拿到同等 gain（非细节恢复），且底行墨量 +10.6%、整卡 mass 6174→6784(+9.9%)（k1.30 +20%）。它把笔画变粗（和已失效的 400→500 补墨同类），不是恢复边缘锐度。若真想要「更肥的字」，它是独立于 gfx.rs 目标链的低成本选项（另立 A/B），**不是**为此重写目标链。注意 `mass` 是 `_aa_edge.py` 按 99 分位前景归一化的等效覆盖面积，非绝对墨量，此处仅作相对参照。

## 结论与建议

- **方案 A 的高质量插值核分支不落地**：插值核（bicubic/lanczos/bilinear）在锁定判据下都不达标，目视更差，不值得 1–2 人日 gfx.rs 目标链改造。**前提**：DComp 现役确为盒式（未真机观测，见上 V4）；若真机发现是 bilinear，结论需重评。
- **方案 A 的「线性光盒式」表述不准（V5）**：脚本用的是覆盖率补偿 `1-(1-a)^k`，非线性光 RGB 平均；独立复核补测了合规线性光（unpremult→EOTF→均值→OETF→repremult），在灰阶单色下与 sRGB 盒式几乎等价（≥80 230 vs 229），不翻转结论。故第二分支准确说是「覆盖率补偿」，有效但加墨。
- 「量」比浏览器标签糊，spike 证据进一步支持：**不是降采样滤波器选得不好**（box 已最优或与参照同级），而是回到了结构性限制——透明灰阶 AA vs 浏览器可能的子像素 AA（未实测），或需要「更肥的字」这一独立方向（覆盖率补偿/补墨，非本 spike 范畴）。
- 下一步给用户拍板：① 收手，把「标签级锐利」列为结构限制（**推荐**）；② 若要「更肥字」另立低成本覆盖率补偿方案 A/B；③ 若怀疑 DComp 不是盒式或坚持要逼到底，做真机 D2D HQC 复核（PIL bicubic≠D2D HIGH_QUALITY_CUBIC，方向性结论稳，精确数值须真机确认）。
