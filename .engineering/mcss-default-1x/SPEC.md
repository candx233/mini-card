# 契约：卡片默认超采样 2× → 1×

任务 slug：`mcss-default-1x` · 档位：标准（产品代码变更） · 建立：2026-11-19

## 用户原话（照录）

> 直接改吧 你不是已经给我对比图了吗

上下文（前两轮）：用户看 `clk_ab_yahei.png`（当前雅黑构建 1× vs 2× 对照）后，判断「1× 原生明显清楚一点」，问「为什么不用 1× 原生」，随后拍板「直接改吧」。

## 目标

把 native 卡片/Dock 的默认超采样倍率从 2× 改为 1×（原生栅格），使桌面实际渲染变锐；保留 `MC_SS` 环境变量作为 A/B 回退开关。

## 验收标准（AC，可判定）

- **AC1 默认值改动**：无 `MC_SS` 环境变量时 `ss_factor()` 返回 1；`MC_SS=2` 仍可强制开回 2×；clamp 仍 1–4。用读码 + 运行验证。
- **AC2 注释一致**：`live.rs:43-46` 那段自相矛盾的注释（一处写「默认1」一处写「默认2×」）统一为「默认1×」并说明切换理由。
- **AC3 编译与测试绿**：`cargo build --release`（native bin）+ 主程序重编，exit 0、零新增警告；相关 cargo test 全过。
- **AC4 运行生效**：单测断言无 `MC_SS` 时 `ss_factor()==1`（`MC_SS=2/9/0` 的覆盖/clamp 也断言）；grep 确认 live 全部建窗点都传 `ss_factor()`；spawn 日志确认启动绘制进程只传 `--live --blur`，无 `--ss` 覆盖。
  - 注：不能用 `--probe weather`（不带 --ss）的 dump 尺寸验证——probe 走 `native/minicard-bin/src/main.rs` 的 `Args.ss`（默认也=1），与 `ss_factor()` 默认值无关，该断言恒真、无法证伪（复核 O1）。
- **AC5 内嵌一致**：主程序内嵌的 native exe hash = 源 `minicard-bin.exe` hash（历史坑：并行编译导致内嵌旧版，font-swap D9）。
- **AC6 真机生效**：重启应用后绘制进程以新版本运行（进程 PID + hash/日志核对）。
- **AC7 独立复核**：只读子代理按 engineering-verify 复核改动与证据，输出缺陷清单；实现者不自发证。

## 非目标

- 不改渲染管线（GRAYSCALE、gamma 2.2、字体、补墨逻辑都不动）。
- 不改 CSS / 字体 / 布局；不改 `MC_SS` 的可配置性（只换默认值）。
- 不做方案 A（gfx.rs 目标链改造）——已由 spike 判定不落地。
- 不改发布资产/tag/latest.json（发版另议，本轮只做到真机生效）。

## 约束

- 单文件默认值改动，可秒级回滚；但触发 native + main 重编（资源构建期嵌入 native exe）。
- 工作树有一堆未提交改动（当日 font-swap 全套），本轮改动叠加其上，不触碰那些文件。
- 平台 Windows；DComp/env 继承机制不变（`main.rs:2289` spawn 无 env_clear，MC_SS 可被外部覆盖）。

## 未知与假设

| 假设 | 错了会怎样 | 处置 |
|---|---|---|
| 1× 在雅黑下大数字/动效不再有明显锯齿 | 若真机见台阶回归，需回退 2× 或局部只对大卡开 2× | 用当前构建 `clk_ab_yahei.png` 已证大字可接受；真机重启后请用户实机确认动效 |
| 用户要的是「全局默认 1×」而非「只对天气卡 1×」 | 若只想要部分卡 1×，需改作用域 | 原话「直接改吧」+ 上下文是全局超采样讨论，按全局默认值改；`MC_SS` 仍是全局开关，无 per-card 先例 |
| 主程序重编会自动嵌入新 native exe | 若嵌入旧版（D9 坑），真机看不到效果 | AC5 显式校验 hash，不一致则按 font-swap 修正流程重编 |

## 决策记录

- 选择改默认值而非删除 2× 代码路径：保留 `MC_SS=2` 回退能力，风险最小、可秒回滚。
- 不动小字补墨逻辑：雅黑下补墨本就是空操作（`text.rs:407-416`），且默认 1× 后 `embold=ss>1` 恒为 false，逻辑自洽无需改。
- 不清理 live.rs 里其它残留（如 probe.rs 的 MC_SS 注释），只改本任务相关段，避免顺手重构。
