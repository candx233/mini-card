# 契约 · 通知卡清除顺序改为自下而上

## 原话（照录）

> 顺序得从小往上清除 注意是顺序 不是动画

理解（在动手前已向用户复述）：清除**顺序**改为「从列表最底下一条开始往上」，底部先滑、顶部最后滑；**动画本身（纯水平两阶段右滑）不变**。用户强调「是顺序不是动画」。

## 目标

把「清除全部」的逐条错开顺序从「顶部（最新）先、往下」改为「底部（最旧）先、往上」，单条删除与右滑动画不变。

## 验收标准（AC）

| # | 判据（可判定） | 判定方式 |
|---|---|---|
| AC1 | 清除全部时第 i 条（snapshot 下标，0=最新=视觉最上）的错开 t0 = `now + (n-1-i)×60ms`：最旧（底）t0=now 先滑，最新（顶）t0=now+(n-1)×60 最后滑 | 单测断言 4 条各自 t0；原生帧看底部行先消失 |
| AC2 | 组头起点仍 = 本组**最后退出**那条的 t0（自下而上时是本组最上/最新那条），组头随本组最后一条滑出 | 单测断言各组 header_exit = 本组 max t0 |
| AC3 | 动画形态不变：滑出段满高满透明只移 dx、补位段收高补位；单条 × 仍纯右滑 | 既有两阶段单测全绿；原生帧文字不淡出/不上飘 |
| AC4 | 不闪回/收敛/错开窗内新消息/窗尾淡入 等前轮修复不被破坏 | 相关单测全绿 |
| AC5 | 卡框/分割线/抬头几何与像素不变（除既有确认↔清除交叉与计数更新） | 单测几何断言 + 帧像素差分 |
| AC6 | demo 同步自下而上错开；单文件无外部引用 | headless Edge `?t=` 渲染 + 源码核对 |
| AC7 | 回归：全量单测绿、`cargo check/build` 通过；独立检验无 P1 及以上 | 命令输出 + 子代理报告 |

## 非目标

- 不改右滑动画形态（两阶段、时长、曲线、位移）
- 不改单条删除行为
- 不改数据模型/布局/配色/其它卡

## 约束

- snapshot 顺序 = 视觉顺序（新→旧、上→下，既有 A1 假设）；自下而上 = 反转 snapshot 下标
- `CLEAR_STAGGER_MS=60` 不变；错开窗口总长仍 `(n-1)×60 + 180`
- 复用 `Motion.exiting` / `group_header_exit`，不新增字段

## 未知与假设（标风险）

| # | 假设 | 风险 / 错了会怎样 |
|---|---|---|
| A1 | 「从小往上」= 从下往上（视觉底部最旧先清） | 若用户实指别的顺序（如按 id 数值），方向会反；已在动手前复述确认口径 |
| A2 | snapshot 下标 = 视觉上下顺序（最新在前=最上） | 若上游快照乱序，视觉顺序会偏；既有约定，本轮不改 |

## 决策记录

| 时间 | 决定 | 影响面 |
|---|---|---|
| 2026-11-17 | 仅反转 `mark_cleared` 的错开下标 `i → (n-1-i)`，组头 max t0 逻辑不变 | 只改一处公式 + 断言 t0 的单测 + demo 的 k→(N-1-k)；动画/prune/animating 窗口不变 |

## 判档

标准档：跨 native + demo、有回归面 → 三件套 + 独立检验。
