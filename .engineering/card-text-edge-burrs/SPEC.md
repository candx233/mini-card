# 契约：修复卡片文字边缘毛刺（字形边缘锯齿）

任务 slug：`card-text-edge-burrs` · 档位：标准（改默认渲染口径 + 重编重部署 + 回归面） · 建立：2026-11-19

## 用户原话（照录）

> 修一下卡片文字边缘溢出的毛刺

用户在澄清问答中选定 artifact = **「字形边缘锯齿/毛边」**（字本身边缘发毛、有锯齿状小凸起），并勾连到「最近默认超采样 2x→1x」。未选「文字溢出卡片被裁断的残笔」「某张具体卡」「发截图按图修」。

## 目标

消除桌面卡片字形斜边/曲边上的阶梯状毛刺，让文字边缘平滑，且不牺牲小字清晰度到不可接受的程度。

## 缺陷说明（缺陷类任务）

- **复现步骤**：当前桌面常驻卡片（时钟大字 49px、天气温度 68px、磁盘 11–12px）放大后看字形斜边；或 `minicard-bin --probe weather --ss 1 --dump` 出图放大。
- **期望**：字形斜边平滑（抗锯齿阶梯不可见或极弱），参考浏览器 Skia 字缘。
- **实际**：ss=1 原生栅格下斜边呈明显阶梯「毛刺」；ss=2 盒式降采样后阶梯被抹平。
- **首次出现**：commit `fb47db3`（2026-11-19 20:06）把 `live::ss_factor()` 默认 2→1。
- **可疑范围**：`native/minicard-bin/src/live.rs:43-58` 的 `ss_factor()` 默认倍率。

### 根因证据（勘察阶段取得）

1. 运行中的绘制进程 `minicard-bin.exe --live --blur 30` 于 19:10:15 启动；当日 native log 中 `超采样 ss=2` 仅出现在 18:20/18:25/18:57 的 `--probe` A/B 取证启动，**live 启动窗口（19:10）无任何 ss=2 行**。因 `mlog!("超采样 ss={}")` 只在 `ss>1` 打印（main.rs:724），证明 live 实际跑 **ss=1**。
2. 受控 A/B（同一雅黑 release、`--probe weather` dump）：`wx_ss1.bgra`(240×180 原生) vs `wx_ss2.bgra`(480×360 盒降到 240×180)。放大对照 `.engineering/card-text-edge-burrs/edge_zoom_ss1_vs_ss2.png`：ss=1 斜边阶梯明显，ss=2 平滑。
3. `fb47db3` diff：`ss_factor()` 由 `.unwrap_or(2)` 改为 `.unwrap_or(1)`，理由「雅黑自带 hinting、1× 更锐、2× 柔化小字」。用户当前反馈表明该取舍对边缘毛刺不成立。

## 验收标准（AC，均可判定）

- **AC1 默认恢复 2×**：无 `MC_SS` 时 `ss_factor()==2`；`MC_SS` 仍可覆盖并 clamp 1–4。单测 `默认超采样…` 改为断言默认 2，`cargo test -p minicard-bin` 对应用例 ok。给出命令与输出。
- **AC2 构建绿**：native release 与 src-tauri release 均 exit 0、零 warning（记录编译输出尾部）。
- **AC3 部署生效**：新 native 二进制 SHA256 = 源 release SHA256；拷贝到 `APPDATA\mini-card\native\0.1.4\minicard-bin.exe`；重启后 live 启动日志出现 `超采样 ss=2` 与 `文字栅格化：超采样 ss=2 → grayscaleEnhancedContrast=0.5`。
- **AC4 边缘平滑（正向）**：重启后用 PrintWindow 抓常驻卡，大字斜边放大对照改前（`live/` 抓图）毛刺消失/显著减弱；给出放大图 + 能反映「硬阶梯被灰阶过渡取代」的客观指标（如边缘带中间灰像素占比 / 灰阶数上升）。注：单行 10–90 坡宽经实测对两档同为 2.00px、不敏感（见 DEFECTS N1），不作为判据。
- **AC5 小字不塌（相邻回归）**：天气「空气质量 优」(12.75px)、磁盘标签(11–12px) 在 ss=2 下墨量不低于 ss=1 基线的 90%（沿用 box 掉墨口径，换雅黑后 2× 补墨失效，须量化确认「柔化」是否抵消锐化收益）。若掉墨 >10% 记为缺陷并上报取舍，不静默接受。
- **AC6 独立复核**：只读子代理按 `engineering-verify` 复核，输出结构化缺陷清单，无未关闭 S1/S2/S3。

## 非目标

- 不改字体（仍系统雅黑）、不改 DWrite gamma/渲染模式/contrast 常量（已钉死且实测最优）。
- 不改任何卡片的布局/字号/间距/颜色。
- 不做发版资产刷新（tag/zip/latest.json）——本任务只改默认渲染口径并重新部署本机，发版另行决定。
- 不改 `--probe` 路径默认（`Args.ss` 仍 1，取证脚本可显式 `--ss`）。
- 不追求 3×/4× 超采样（收益未证、成本上升）。

## 约束

- Windows；D2D/DWrite 自绘；透明预乘交换链 + DComp 盒式降采样。
- 发布包结构：native exe 内嵌进 src-tauri（`build.rs`），APPDATA 解压路径 `native/0.1.4/`。
- 串行重编：先 native release，再 src-tauri release（历史上并行导致内嵌旧 hash）。
- 工作树有大量其它任务的未跟踪 .engineering 资产，均不碰。

## 未知与假设

| 假设 | 错了会怎样 | 处置 |
|---|---|---|
| 用户说的「毛刺」= 字形斜边阶梯（已由其选项确认） | 若是「溢出卡边的残笔」则 2× 无关 | 已澄清选定锯齿项；若改后无效应重新追问 |
| ss=2 的柔化不显著损害小字可读性 | 小字掉墨 >10% 会让「清晰」诉求回退 | AC5 量化；超阈值记为缺陷上报取舍 |
| 当前二进制为 post-commit（默认 1×） | 若是 pre-commit（默认 2×）则用户看到的是 2×，改默认无效 | 日志已证 live 无 ss=2 行=跑 1×；重启后 AC3 日志复核 |

## 决策记录

- 选「恢复 ss 默认 2×」而非「调 gamma/contrast」：斜边阶梯是采样率问题，gamma 已在上限 2.2、contrast 在灰阶下无差异（text.rs 实测），只有提高栅格采样能抹平阶梯。
- 选「恢复 2×」而非「3×/4×」：2× 是本项目 0.1.3–0.1.4 长期默认、边缘收益已证；更高倍率成本未评，属非目标。
- MC_SS 覆盖保留：若个别机器 2× 有性能问题，用户可 `MC_SS=1` 自助回退，不写死。
