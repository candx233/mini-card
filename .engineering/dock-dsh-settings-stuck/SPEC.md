# 契约：Dock 页 DSH 条目设置面板无法收起

任务 slug：`dock-dsh-settings-stuck` · 档位：标准（代码修复 + 真机验收 + 独立复核） · 建立：2026-11-19

## 用户原话（照录）

> 主界面dock页的dsh的项目设置一直是打开的状态 点了按钮都收起不了 修复一下

> （补充）是mini card的主界面dock页哈

## 目标

修复 mini-card 主界面 Dock 页中「DeepSeek Harness」条目的设置面板始终展开、点击「条目设置」按钮无法收起的问题，使该按钮对该条目也能正常开/合切换，且不影响其它条目的既有开合行为。

## 复现步骤与期望 / 实际

- **现场数据**：`%APPDATA%\mini-card\config.toml` 的 `[[dock.items]]` 中，DeepSeek Harness 条目 `id = ""`（空字符串），其余条目 id 均为非空（如 `5af3b579`、`net-ease`）。
- **复现**：主界面 → Dock 页（页面 5）→ 找到 DeepSeek Harness 行 → 观察其 `.dopts` 设置面板。
- **期望**：面板可开可合；点击「条目设置」按钮应切换展开状态。
- **实际**：面板一进页面就是展开（`.dopts.on` 常驻）；反复点击「条目设置」按钮无效，始终展开。
- **首次出现**：无法从用户处获知具体版本；由现场配置（空 id）+ 前端哨兵值共同触发，属潜伏缺陷。

## 根因（代码证据）

`web/index.html` Dock 页三处：

- L2572：`var DOCK_OPT_OPEN = '';` —— 用空字符串 `''` 表示「没有条目面板展开」。
- L2692：`'<div class="dopts' + (DOCK_OPT_OPEN === it.id ? ' on' : '') + '">'` —— 渲染时比较。
- L2706：`DOCK_OPT_OPEN = (DOCK_OPT_OPEN === it.id) ? '' : it.id;` —— 点击时切换。

DSH 条目 `id === ''`，于是：

1. 初始 `'' === ''` 为真 → 面板渲染出 `on` 类 → 一进页面就展开；
2. 点击时 `('' === '') ? '' : it.id` → 求值为 `''`，值未变 → 重渲染后仍展开；再点亦同 → 永远收不起来。

即：**哨兵值与合法数据值域重叠**（空串既是「未展开」标记，又是 DSH 的真实 id）。

## 验收标准（AC）

- **AC1 默认收起**：Dock 页加载后，DSH（空 id）条目的 `.dopts` 不含 `on` 类（其余条目原有默认状态不变）。
- **AC2 开合切换**：点击 DSH 条目的「条目设置」按钮 → 面板展开（含 `on`）；再点 → 收起；连续多次按「开→合→开→合」交替，状态正确。
- **AC3 无回归**：非空 id 条目的开合行为与修复前一致；同一时刻仍最多一个条目面板展开（互斥性保持）。
- **AC4 逻辑可证**：用可复跑脚本驱动真实的 `renderDockList` 开合状态机，覆盖空 id 与非空 id 两类条目，输出与 AC1–AC3 一致。
- **AC5 真机生效**：`web/index.html` 改动后重编 release，exe mtime 晚于 index.html，运行实例已重启并加载新逻辑。
- **AC6 独立复核**：只读子代理按 `engineering-verify` 复核，输出结构化缺陷清单；实现者不自发合格证。

## 非目标

- 不修改用户 `config.toml`（不给 DSH 条目补 id）——修的是代码里哨兵与数据值域重叠的缺陷，而非个别数据；这样对任何空 id 条目都健壮。
- 不改 Rust 侧 dock 命令、不改 dock.html（桌面原生条）、不改其它页面。
- 不顺手重构 Dock 页其它逻辑。

## 约束

- 改动文件仅 `web/index.html`（前端资源在 release 构建时嵌入 exe，改完必须重编 release 并重启实例才生效）。
- Windows 11 + WebView2；mini-card 0.1.4。
- 回滚：`git checkout -- web/index.html` 秒级回滚。

## 未知与假设

| 假设 | 错了会怎样 | 处置 |
|---|---|---|
| 空 id 是历史/手工配置产物，`dock_add` 生成的是非空 short_id | 若新增条目也能生成空 id，则还可能复发 | 已从 `main.rs:3136` 确认 `dock_add` 用 `dock::short_id()` 生成非空 id；前端仍按「任何 id 值都合法」来修，不依赖 id 非空 |
| 用 `null` 作哨兵不会与任何 `it.id` 相等 | 若某条目 id 被序列成 `null`/`undefined` 则又冲突（见残余风险 V2） | `it.id` 来自 TOML String，`native/minicard-core/src/config.rs:132` 为 `pub id: String`（非 Option），serde 输出必为字符串；`null === <string>` 恒为假。V2 经独立复核判定为不可达理论边界 |
| 「项目设置」= `.dopts` 条目设置面板（启动参数/自定义图标/分组分隔线） | 若用户指的是别的面板则修错地方 | 用户明确「主界面dock页」「收起不了」；Dock 页唯一可开合面板即 `.dopts`，按钮 title 为「条目设置」，语义吻合 |

## 决策记录

- 修复方案：把 `DOCK_OPT_OPEN` 的「未展开」哨兵从 `''` 改为 `null`（`null` 不在 `it.id` 的值域内）。共两处：声明 L2572 与点击切换 L2706；L2692 比较式不变。
  - 影响面：仅 Dock 页条目设置面板的开合；对非空 id 条目行为等价。
  - 理由：最小、精准、根治「哨兵与数据值域重叠」，对空 id 及一切可序列化的字符串 id 都健壮；不改数据、不改 Rust。理论上的非字符串 id（null/undefined）不可达，见残余风险 V2。

## 残余风险 / 待用户拍板

- **V1（S3，既有设计局限，非本次引入）**：面板按 `it.id` 键控，若配置里存在重复 id（含多条空 id），展开其中一条会让所有同 id 条目一起展开，互斥性失效。触发条件：手工编辑 `config.toml` 造出重复 id——UI 路径造不出（`main.rs:3136-3139` 的 `dock_add` 用 `dock::short_id()` 并循环避开所有既有 id，保证唯一）。本次现场配置只有一条空 id，不受影响。旧代码下重复 id 是「永久同时展开且都点不动」，本次修复后至少能一起开合，严格变好。改前端键控语义（如改用行索引）会引入 reorder 后面板跳到别条目的新 bug，故不改。**用户已拍板走 B 方案（配置加载层保证 id 唯一）根治，见下方第 3 轮契约。**
- **V2（S4，不可达理论边界）**：若 `it.id` 为 JS `null`/`undefined`，`null === null` 会令面板默认展开且点不动（复现原症状）。但 `config.rs:132` `pub id: String` 非 Option、TOML 无 null、serde 必输出字符串，`get_dock` 无注入 null 的路径——数据域内不可达，不修。
- **真机 GUI 肉眼点击未做**：浏览器扩展离线，开合结论由驱动真实源码片段的状态机脚本 + 独立复核给出；如需绝对确认可补一次人工实点。
- **exe 内嵌 index.html 为压缩资产**：无法逐字节证明嵌入的是新代码；以「exe mtime 12:56:33 > index mtime 12:54:27 + codegen asset 12:55:21」时间点证据佐证（独立复核已核）。
